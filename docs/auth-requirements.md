# Supabase認証機能実装 要件定義書

## 1. 概要

### 1.1 目的

既存のジョーモカルタタイピングゲームアプリケーションに、Supabase Auth（@supabase/ssr）を使用したユーザー認証機能を実装する。これにより、ユーザーごとのスコア管理、プロフィール管理、ランキングの個人化を実現する。

### 1.2 スコープ

- ユーザー認証（登録、ログイン、ログアウト）
- セッション管理（SSR対応）
- プロフィール管理
- 既存機能との統合（スコア、ランキング）

### 1.3 技術スタック

- **フレームワーク**: SvelteKit 2
- **認証ライブラリ**: @supabase/ssr, @supabase/supabase-js
- **バックエンド**: Supabase Auth
- **デプロイメント**: Vercel

## 2. 機能要件

### 2.1 認証機能

#### 2.1.1 ユーザー登録

- メールアドレスとパスワードによる新規登録
- メールアドレス確認機能
- パスワード強度の検証（最低8文字、英数字混在推奨）
- 利用規約への同意確認

#### 2.1.2 ログイン

- メールアドレスとパスワードによるログイン
- ソーシャルログイン対応（Google、GitHub）
- Remember Me機能（セッション延長）
- ログイン失敗時のエラーハンドリング

#### 2.1.3 ログアウト

- セッションの完全な削除
- すべてのデバイスからのログアウトオプション
- ログアウト後のリダイレクト処理

#### 2.1.4 パスワード管理

- パスワードリセット機能（メール送信）
- パスワード変更機能（要現在パスワード）
- パスワード強度インジケーター

### 2.2 セッション管理

#### 2.2.1 SSR対応

- サーバーサイドでのセッション検証
- Cookieベースのセッション管理
- CSRFトークンによる保護

#### 2.2.2 セッション維持

- 自動リフレッシュトークン処理
- セッションタイムアウト設定（デフォルト: 1週間）
- アクティビティに基づく延長

### 2.3 プロフィール機能

#### 2.3.1 基本情報

- ニックネーム（必須、一意性チェック）
- アバター画像（オプション）
- 自己紹介文（オプション、最大200文字）
- メールアドレス表示/非表示設定

#### 2.3.2 統計情報表示

- 総プレイ回数
- 最高スコア（難易度別）
- 平均スコア
- お気に入りのカルタ

### 2.4 既存機能との統合

#### 2.4.1 スコア管理

- ユーザーIDとスコアの紐付け
- ゲストプレイとログイン済みプレイの区別
- 過去のスコア履歴管理

#### 2.4.2 ランキング機能

- ユーザー名の表示（ニックネーム使用）
- 自分のスコアのハイライト表示
- フレンド機能（将来実装予定）

#### 2.4.3 お気に入り機能

- ユーザーごとのお気に入りカルタ管理
- クラウド同期（ログイン時）
- ローカルストレージとの同期

## 3. 非機能要件

### 3.1 セキュリティ

#### 3.1.1 認証セキュリティ

- HTTPS通信の強制
- パスワードのハッシュ化（Bcrypt）
- SQLインジェクション対策
- XSS対策

#### 3.1.2 セッションセキュリティ

- Secure Cookieの使用
- HttpOnly Cookieの使用
- SameSite属性の設定
- セッションフィンガープリント

### 3.2 パフォーマンス

#### 3.2.1 レスポンス時間

- ログイン処理: 2秒以内
- セッション検証: 100ms以内
- プロフィール読み込み: 1秒以内

#### 3.2.2 並行性

- 同時ログイン数: 制限なし
- デバイス間同期: リアルタイム

### 3.3 可用性

#### 3.3.1 エラーハンドリング

- ネットワークエラー時のフォールバック
- Supabaseサービス障害時の対応
- グレースフルデグラデーション

#### 3.3.2 互換性

- モバイルブラウザ対応
- 主要ブラウザサポート（Chrome, Firefox, Safari, Edge）
- プログレッシブエンハンスメント

### 3.4 保守性

#### 3.4.1 ログ

- 認証イベントのログ記録
- エラーログの収集
- ユーザー行動分析（プライバシー配慮）

#### 3.4.2 監視

- ログイン成功率の監視
- セッションエラー率の監視
- パフォーマンスメトリクス

## 5. API設計

### 5.1 認証エンドポイント

#### POST /auth/login

```typescript
interface LoginRequest {
	email: string;
	password: string;
	rememberMe?: boolean;
}
```

#### POST /auth/signup

```typescript
interface SignupRequest {
	email: string;
	password: string;
	nickname: string;
	agreeToTerms: boolean;
}
```

#### POST /auth/logout

```typescript
interface LogoutRequest {
	allDevices?: boolean;
}
```

## 9. リスクと対策

- **リスク**: Supabaseサービスの障害

### 9.2 セキュリティリスク

- **リスク**: 認証情報の漏洩
- **対策**: 定期的なセキュリティ監査、ペネトレーションテスト

### 9.3 ユーザビリティリスク

- **リスク**: 複雑な認証フローによる離脱
- **対策**: シンプルなUIデザイン、ソーシャルログインの提供
